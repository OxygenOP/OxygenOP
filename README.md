## Featured: SecretVariable

[![npm](https://img.shields.io/npm/v/@secretvariable/cli?label=%40secretvariable%2Fcli)](https://www.npmjs.com/package/@secretvariable/cli)
[![CI](https://github.com/OxygenOP/SecretVariable/actions/workflows/ci.yml/badge.svg)](https://github.com/OxygenOP/SecretVariable/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](https://github.com/OxygenOP/SecretVariable/blob/main/LICENSE)

**An open-source, self-hosted home for your team's `.env` files.** Teams share environment files in chat threads and wikis, and nobody knows which copy is current. SecretVariable keeps them in one place:

- every change is a numbered version you can compare and roll back
- access is set per environment, so a contractor can have `staging` and never see `production`
- a CLI that switches environments safely and can inject variables without writing a file
- encrypted at rest, with an audit log, two-step verification and scoped tokens for CI
- one Docker container plus PostgreSQL, MIT licensed

```bash
npm install -g @secretvariable/cli
svar env use staging     # switch environment and update your .env in one step
```

[Website](https://www.secretvariable.com) · [Documentation](https://www.secretvariable.com/docs) · [Source](https://github.com/OxygenOP/SecretVariable)

It is early software, and honest about its limits: the encryption is server-side, so whoever runs the server can read the secrets.
